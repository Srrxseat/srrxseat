# Handoff — TradingView indicator `pine/ema-multi.pine`

สรุปสถานะสำหรับ session ใหม่ที่จะมารับงานต่อ

## สิ่งที่ทำอยู่

Indicator Pine Script v6 ตัวเดียวรวม 2 อย่าง สำหรับผู้ใช้เทรดคริปโตบน TradingView (OKX: BTCUSDT / BCHUSDT, ดูหลาย TF ตั้งแต่ 1D ถึง 1W)

1. **EMA 7 / 30 / 50 / 100 / 200** + เส้นสำรอง 1 เส้น (ปิดไว้, 400) — ปรับความยาว/สี/เปิด-ปิดได้ทุกเส้น
2. **Price Imbalance (FVG)** แบบ 3 แท่ง — `low > high[2]` = ฝั่งซื้อ, `high < low[2]` = ฝั่งขาย

ไฟล์: `pine/ema-multi.pine` · เอกสารผู้ใช้: `pine/README.md` · แบรนช์: `claude/tradingview-custom-indicator-0263yj`

## รอบล่าสุด: แก้ EMA ไม่ขยับตามกราฟ (รอผู้ใช้ยืนยัน)

แก้ 3 จุด:

1. แยก **สวิตช์ `ล็อก Timeframe ของ EMA`** (bool, ปิดเป็นค่าเริ่มต้น) ออกจากช่อง dropdown TF
   เดิม `useHtf = tf != ""` — ถ้า dropdown มีค่าค้างในการตั้งค่าที่เซฟไว้ EMA จะถูกล็อกเงียบๆ
   ตอนนี้ `useHtf = emaLock and tf != "" and tf != timeframe.period` → สวิตช์ปิด = ตามกราฟเสมอ ไม่ว่า dropdown จะค้างค่าอะไร
2. **ถอด `max_bars_back = 500`** ออกจากบรรทัด `indicator()` (ตามสมมติฐานข้อ 2 เดิม)
3. เพิ่ม **แถวสถานะแถวล่างสุดของตารางสรุป**: `TF กราฟ | <period> | EMA ตามกราฟ (เขียว) / EMA ล็อก <tf> (ส้ม)`
   ใช้ยืนยันเวอร์ชันโค้ด + สถานะการล็อกได้ในภาพเดียว ไม่ต้องเปิด Settings

**ถ้ายังไม่หาย** ให้ทำข้อพิสูจน์ข้อ 4 ด้านล่าง (วางทับ `Moving Average Exponential` ของ TradingView) ก่อนแก้โค้ดต่อ

## ⚠️ ปัญหาเดิม (บริบทเต็ม)

**อาการ: สลับ Timeframe ของกราฟแล้วเส้น EMA ไม่ขยับตาม** — ผู้ใช้ยืนยันว่ายังเป็นอยู่หลังแก้รอบล่าสุด

สิ่งที่ลองไปแล้วและ **ไม่ใช่** สาเหตุ (หรือแก้แล้วยังไม่หาย):

- ตั้งช่อง "ล็อก Timeframe" เป็น `Chart` แล้ว — ยังเป็น
- เปลี่ยนมาใช้ `ta.ema(src, len)` ตรงๆ เมื่อ `tf == ""` แทน `request.security` (commit `97df8da`) — ผู้ใช้บอกยังเป็นอยู่
- เพิ่มป้าย ⚠ เตือนบนกราฟเมื่อมีการล็อก TF

สมมติฐานที่ยังไม่ได้ตรวจ (แนะนำไล่ตามลำดับ):

1. **ผู้ใช้อาจยังรันโค้ดเวอร์ชันเก่าอยู่** — เกิดขึ้นมาแล้ว 2 ครั้งใน session นี้ ผู้ใช้กด Save เป็นสคริปต์ใหม่ แต่บนกราฟยังเป็นตัวเก่าที่ add ไว้ **ให้ยืนยันเวอร์ชันก่อนเสมอ**: ขอภาพ Settings ว่ามีป้าย `⚠ EMA ล็อกที่ TF` หรือค้นคำว่า `useHtf` ในโค้ดเจอไหม
2. `max_bars_back = 500` ในบรรทัด `indicator()` — ใส่ไว้ตอนไล่ error อาจไม่จำเป็นแล้วและอาจมีผลข้างเคียง ลองถอดออกดู
3. อาจเป็นสเกลของกราฟ ไม่ใช่ค่า EMA — เคยเจอมาแล้วครั้งหนึ่ง (แกนราคายืดไป 208,000 ทั้งที่ราคา 55k–90k เพราะ auto-scale รวมเส้นเทรนด์ไลน์ที่ผู้ใช้ลากเอง)
4. **วิธีพิสูจน์ที่ยังไม่ได้ทำ**: ให้ผู้ใช้เพิ่ม indicator ในตัวของ TradingView (`Moving Average Exponential`, length 200) วางทับเส้นแดงของเรา ถ้าสองเส้นทับกันสนิท = โค้ดถูก ปัญหาอยู่ที่การตั้งค่า/สเกล ถ้าไม่ทับ = โค้ดผิดจริง

## บทเรียนที่เจ็บมาแล้ว (อย่าทำซ้ำ)

| ข้อจำกัดของ Pine | ผลที่เกิด |
| --- | --- |
| `plotcandle` **ไม่มี** พารามิเตอร์ `offset` | CE10120 — ต้องเลื่อนตำแหน่งด้วยการเช็คเงื่อนไขย้อนหลัง `paintBull[n]` แล้วระบายแท่งปัจจุบันแทน |
| index ของ series ต้องเป็นค่าคงที่ | `open[shift]` ที่ `shift` เป็นตัวแปร → Indicator error ต้องเขียน `fvgAt == 1 ? open[1] : ...` |
| `plotshape` รับ `size` เป็น const เท่านั้น | ต้องแยก plotshape เป็นชุดตามขนาด เลือกเปิดทีละชุดด้วย bool |
| ลิมิต **64 plot** ต่อสคริปต์ และ "สีที่ส่งเป็น series ถูกนับเป็น plot ด้วย" | RE10140 — `plotcandle` ที่ส่งสีไดนามิกกิน 7 plot ต่อชุด ต้องรวมฝั่งซื้อ/ขายเป็นชุดเดียวแล้วเลือกสีตามทิศทาง **เหลือโควตาราว 38 plot ถ้าจะเพิ่มของใหม่** |
| กล่อง (`box`) ยึดขอบที่จุดกลางแท่ง | กล่องกว้าง 1 แท่งจะคร่อมสองแท่งเสมอ ไม่มีทางตรงกลางแท่งพอดี → จึงเพิ่มโหมด `ระบายสีแท่งเทียน` ด้วย plotcandle |

## โครงสร้างโค้ดปัจจุบัน (ไล่จากบนลงล่าง)

1. input 5 กลุ่ม: ทั่วไป / ความโปร่งใส / เส้น EMA / Price Imbalance / Diamond (Back Testing)
2. `f_ema()` — เลือกระหว่าง `ta.ema` (ตาม TF กราฟ) กับ `request.security` (เมื่อล็อก TF)
3. plot เส้น EMA + `fill()` โซนแนวโน้ม (สี + ความจาง-เข้ม แยกขาขึ้น/ขาลง มี checkbox ปิดแยกฝั่ง)
4. ป้ายชื่อท้ายเส้น — กระจายแนวนอนกันทับด้วย `lblGap`
5. ตรวจจับ FVG → `newBull` / `newBear` (กรองขนาดด้วย % ราคา และ ATR14)
6. เก็บสถานะ imbalance ใน array 6 ชุด (`fBox` `fMid` `fTop` `fBot` `fDir` `fBar`) ติดตามจนถูกเติมเต็ม
7. ระบายสี 3 โหมด (`ระบายสีแท่งเทียน` / `ระบายเฉพาะช่วงช่องว่าง` / `กล่อง`) + `fvgAt` คุมตำแหน่ง 0–5
8. diamond marker · ตารางสรุป · alertcondition 8 แบบ

## สไตล์การทำงานที่ผู้ใช้ชอบ

- คุยไทย, ชอบคำอธิบายสั้นๆ ตรงประเด็น พร้อมบอกว่าแก้อะไรตรงไหน
- ส่งภาพหน้าจอมาให้ดูแทนการพิมพ์ error — **ให้ไล่อ่านรายละเอียดในภาพก่อนเดา** (title bar, status line, ค่าใน Settings บอกเวอร์ชันที่รันอยู่ได้)
- ต้องการปรับทุกอย่างจากหน้า Settings ไม่ต้องแก้โค้ด
- commit ทุกครั้งที่แก้เสร็จ แล้ว push ขึ้นแบรนช์เดิม + แนบไฟล์ให้ด้วย
